# Milestone 1, part 5: the database schema, part 1 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the profile database's first 22 tables as SQLAlchemy Declarative classes, with the notebook's table and column names, checked against the notebook's own DDL. Also build the engine that opens the database, and the rule that drops and recreates Steam tables when their schema changes.

- **Copied from the notebook (21):** 8 lookups, `app`, `app_text`, 9 classification tables and 3 credit tables.
- **New:** one table for Steam's compatibility test results.

**Architecture:**

- `src/steam_manager/db/engine.py` opens `steam.sqlite` with WAL and foreign keys on.
- `src/steam_manager/db/schema/` declares the tables on one `SteamBase`.
- `ensure_steam_schema(engine)` compares a fingerprint of the declared DDL with the one stored in the file. When they differ, it drops the Steam tables, creates them again, and tells the caller to replay the raw archive.
- **The check:** a test builds the notebook's DDL (committed as a fixture) and the declared schema in two in-memory databases. It compares every shared table's columns, keys, foreign keys and unique indexes; every intended difference is listed in the test.

**Tech Stack:** Python 3.15, SQLAlchemy 2.1.8, SQLite (STRICT tables), pytest.

**Spec:** `docs/superpowers/specs/2026-11-14-steam-manager-design.md` (*Database*, *Loader*, *Reference material*). The notebook's schema is `../steam-collection/steam-database/steam-database.ipynb`, cell 2. ADR 0003 covers SQLite per profile.

**Where this fits:** stage 5 of milestone 1. Next comes schema part 2 (relations, season passes, offers, media, requirements, review tables, `wishlist_item`, `followed_app`, the HowLongToBeat tables later) with the views. Then the loader, which fills these tables from the archive.

## Global Constraints

- Python `>=3.15`; lines up to 99; complete typing; Sphinx docstrings without `:type:`/`:rtype:`, attributes documented.
- Test first, and watch every test fail before its code exists. Tests mirror `src/`: `db/engine.py` → `tests/steam_manager/db/test_engine.py`, `db/schema/apps.py` → `tests/steam_manager/db/schema/test_apps.py`.
- SQLAlchemy 2.1+ for every interaction with SQLite. `STRICT` tables accept only INTEGER, TEXT, REAL, BLOB and ANY, so columns use `Integer`, `Text`, or the `Flag` type below; never `String`, `Boolean` or `DateTime`, whose DDL STRICT rejects.
- The schema keeps the notebook's table and column names wherever the concept is unchanged (spec *Database*).
- One pull request, never a draft, `just check` and `just docs` first, merged by rebase. Before 2026-11-18 there is no Sourcery review, and the 150,000-character limit is waived.

## Review Focus

1. A release changes one Steam column. Opening a database built by the previous release must drop and recreate the Steam tables and report it, not fail on the first insert or keep the old layout. Test in Task 5.
1. A table or column renamed by mistake (`unvailable` vs `unavailable`, `appid` vs `app_id`) fails the notebook comparison, naming the table and column. Test in Task 2.
1. A STRICT violation: a flag written as `"yes"` is refused instead of stored loosely. A number given to a text column is converted to text, as STRICT does without loss. Test in Task 3.
1. A row pointing at an app nothing describes (`app_tag.appid` of a missing app) fails while foreign keys are on. Test in Task 1.
1. Two credits named "Valve", one with a creator id and one without, are both allowed. Two without a creator id are not (the partial unique index). Test in Task 4.

### Task 5: Dropping and recreating Steam tables when their schema changes

**Files:** modify `src/steam_manager/db/schema/__init__.py` (it imports every schema module, so `SteamBase.metadata` is complete); create `src/steam_manager/db/steam_schema.py`; test `tests/steam_manager/db/test_steam_schema.py`.

**Interfaces (produces):**

- `def fingerprint() -> str`: the SHA-256 hex of the compiled `CREATE TABLE` and `CREATE INDEX` statements of `SteamBase.metadata`, sorted by name.

- `def ensure_steam_schema(engine: Engine) -> bool`:

  - creates the `steam_schema` table when missing;
  - when its stored fingerprint differs from `fingerprint()`, or is missing, drops every Steam table (`SteamBase.metadata.drop_all`), creates them and stores the new fingerprint;
  - returns `True` when it (re)created the tables, `False` when they were current.

- [ ] **Step 1: failing tests**

  - `test_a_new_database_gets_every_table` (`True`; all 22 tables present)
  - `test_a_current_database_is_left_alone` (a second call → `False`; a row inserted in between survives)
  - `test_a_changed_schema_drops_and_recreates` (Review Focus 1): overwrite the stored fingerprint with `"older"`; the call returns `True`, the row is gone, and the tables are back
  - `test_the_fingerprint_follows_the_ddl` (stable across calls; a throwaway metadata with one more column gives another)

- [ ] **Steps 2–5:** fail; implement; pass; `just check`, `just docs`; commit `feat(db): rebuild Steam tables when their schema changes`.
