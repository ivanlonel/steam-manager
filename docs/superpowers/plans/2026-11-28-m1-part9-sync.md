## Context

The roadmap (`docs/superpowers/plans/README.md`) marks the **sync** as next. The pieces already exist:

- part 2: the transport;
- part 3: every Steam endpoint;
- part 4: the raw archive, with `Archive.fetched_at`, which was built for staleness;
- part 8: the loader.

Nothing yet decides what to fetch, fetches it, and loads it. There are no profiles either, so no data folder and no settings. This stage adds both as library code. The CLI wires them into commands in part 10.

**The owner decided on 2026-11-28:** the apps that the account apps point at get a full entry too, one level deep. Those are the related apps (parent game, demos, playtests, season pass, free-to-play version, engine) and the DLC on the store page. Account apps in milestone 1 are the wishlist and the followed apps.

**Goal:**

- `open_profile(folder)` gives a profile whose database reflects its archive.
- `sync(profile, transport, …)` fetches what is stale, step by step. It archives as it goes, loads after each step, and survives interruption.

**Architecture:** two modules, each with a test module that mirrors it.

- **`src/steam_manager/profiles.py`:**
  - the `Settings` model;
  - the data folder;
  - profile folders;
  - `open_profile`, which runs `ensure_steam_schema`, then `load`, then `create_views`.
- **`src/steam_manager/sync.py`:**
  - the steps;
  - staleness, read from `Archive.fetched_at`;
  - fetching through the existing endpoint functions;
  - `asyncio.to_thread(load, …)` after each step.

**Tech Stack:** Python 3.15, asyncio, httpx (through `Transport`), Pydantic 2 (`Settings`), SQLAlchemy 2.1 Core, pytest with `tests/_fakes.py`'s `httpx.MockTransport` fakes.

**Spec:** `docs/superpowers/specs/2026-11-14-steam-manager-design.md`:

- *Profiles and settings*, *Catalog depth*, *Commands*, *Steam endpoints*, *Transport* and *Sync*;
- *Left to the builder*: default maximum ages.

## Global Constraints

- **Code:** Python `>=3.15`; lines up to 99; complete typing; Sphinx docstrings. Tests come first, each seen failing. `src/steam_manager/x.py` → `tests/steam_manager/test_x.py`.
- **Paths:** `pathlib.Path` only. No global mutable state: `environ`, `now` and `transport` are parameters.
- **Secrets:** no query string, token or cookie in a report, log line or exception. Failures are reported by `str(FetchError)`, which names the endpoint only.
- **Network:** every request goes through `Transport` and the part 3 endpoint functions; no new endpoint. Pacing is theirs.
- **Database:** one synchronous writer. `load` runs through `asyncio.to_thread`; SQLAlchemy sets `check_same_thread=False` for file databases (checked in `sqlalchemy/dialects/sqlite/pysqlite.py`, 2026-11-28).
- **Vocabulary:** *profile*, *sync*, *home country*, *fallback country*, *account apps*, *full entry*, *light entry*, *answer*, *rebuild*. Never "refresh", "update", "pull", "user apps" or "my games".
- **Pull request:** one, never a draft, under 150,000 characters (`git diff main...HEAD | Measure-Object -Character`). If it's over, split it after Task 2: profiles first, sync second. `just check` and `just docs` pass first.

| Settings file                       | JSON written by Pydantic: `steamid`, `home_country`, `fallback_countries` (default `["US"]`), `language` (default `english`), and `max_ages`. `max_ages` holds only the user's overrides, as ISO 8601 durations.                                                                                                                                        | Read and written by the standard library and Pydantic. Keeping only overrides means a release's new defaults reach existing profiles.                                 |
| Countries                           | Stripped, upper-cased, and refused unless they're two ASCII letters. Fallbacks drop the home country and repeats, keeping the first.                                                                                                                                                                                                                    | The owed item: `br` must not hide prices. Dropping a duplicate is unambiguous, so it isn't refused.                                                                   |
| Language                            | Steam's API language code, refused unless it's in `API_LANGUAGES`, which maps each code to its ELanguage number for `GetStoreCategories`. The table comes from the Steamworks language page (2026-11-28), matched by name to the loader's `LANGUAGES`. Malay has no known number, so it's left out.                                                     | A typo would silently give English.                                                                                                                                   |
| Maximum ages (defaults)             | Lookups 7 days; wishlist and followed apps 1 hour; listing 7 days; full entries 1 day; current players 1 day; exact review counts 7 days; histograms 7 days. Light entries go stale with their listing. Genre names are asked only for a genre without a name.                                                                                          | One request each for the account lists, so a re-run within the hour after an interruption skips them. Prices change daily. Histograms cost 1 s per app.               |
| Step order                          | `lookups`, `wishlist`, `followed`, `catalog`, `apps`, `reviews`, whatever order they're given in. A load follows each step.                                                                                                                                                                                                                             | The loader checks store categories while it reads apps, the apps step reads the account lists from the database, and the reviews step reads review summaries from it. |
| Fallback countries                  | Country passes over a set of apps. The home country asks every stale app. Fallback country *n* asks the stale apps that no earlier country sells, meaning no `app` row with `success = 1` and a `store_country` among the earlier countries. A load follows each pass.                                                                                  | The spec's rule. It reads what the loader already ranked, so nothing is parsed twice.                                                                                 |
| Catalog step                        | Each country's listing is re-listed when its `listing` answer is stale. A fallback's light entries are archived only for apps that no earlier country's latest listing holds; the listing answer itself is archived whole. Answers are archived a page (1,000) at a time.                                                                               | "Fallback only for apps the home country doesn't sell". It also meets the owed item "bound each `put` batch".                                                         |
| Apps step                           | Full entries for the account apps (country passes), then for the referenced apps (country passes). Then current players for the account apps, and genre names: one `appdetails` call per unnamed genre, skipping genres an earlier call's app also has.                                                                                                 | The spec, and the notebook's `get_genre_names`.                                                                                                                       |
| Reviews step                        | Exact counts through `exact_review_answers`, for account apps with more than 100 filtered reviews, or for every such app with `catalog_reviews=True`, largest first. Staleness is read from the key of the app's own purchase type (`1` if free, else `0`). Then histograms for the account apps.                                                       | *Catalog depth*.                                                                                                                                                      |
| Full catalog                        | `fetch_full_catalog(profile, transport, …)`: country passes over every app with `is_listed = 1`. It resumes through staleness.                                                                                                                                                                                                                          | The spec's `catalog fetch --full`.                                                                                                                                    |
| Failures                            | A `RequestFailedError` skips its unit (one batch of 100, one app, one listing, one lookup), goes to `SyncReport.failed`, and the step goes on. A `ListingMismatchError` skips that country's listing answer. A `FailureStreakError` stops the sync: what was archived is loaded, `stopped` says why, and no exception escapes. Loader errors propagate. | The notebooks' `per_app`, and the spec's "a run of failures stops the sync".                                                                                          |
| Archive writes                      | Per-app answers are put every 100 (`ARCHIVE_CHUNK`), and a batch's answers together. A stop still puts what's pending.                                                                                                                                                                                                                                  | An interruption loses at most 100 answers; no transaction per answer.                                                                                                 |
| `status`, `profile remove`          | Left to part 10.                                                                                                                                                                                                                                                                                                                                        | They're CLI-only; the staleness helper here is what `status` will reuse.                                                                                              |

## Review Focus

1. **Steam fails mid-step (a streak).** The sync stops without raising, `stopped` names the host, and what was archived is loaded. A second sync fetches only what is still stale. Test in Task 6.
1. **A sync killed between archiving and loading.** The next `open_profile` loads what was archived. Test in Task 2.
1. **Countries typed loosely** (`br`, `us`, `BR` among the fallbacks, `BRA`, `B1`). The first three are normalized; the last two are refused with a `ValidationError`. Test in Task 1.
1. **An app the home store sells is never asked in a fallback; one it doesn't sell is; one nobody sells is asked in every fallback.** Test in Task 6.
1. **One failed request** (one `GetItems` batch, one app's reviews). Only that unit is skipped, the failure names the endpoint without a query string, and the rest of the step lands. Tests in Tasks 4 and 6.

### Task 4: The sync's frame, and the lookups, wishlist and followed steps (`sync.py`)

**Interfaces (produces):**

- `class Step(StrEnum)`: `LOOKUPS`, `WISHLIST`, `FOLLOWED`, `CATALOG`, `APPS`, `REVIEWS`, valued `"lookups"` and so on.

- `ARCHIVE_CHUNK: Final = 100`.

- `@dataclass class SyncReport`:

  - `fetched: Counter[str]`: answers archived, by kind;
  - `failed: list[str]`: requests that failed after their retries;
  - `load: LoadReport`: every load, merged;
  - `stopped: str | None = None`.

- `async def sync(profile: OpenProfile, transport: Transport, *, steps: Collection[Step] = tuple(Step), force: bool = False, catalog_reviews: bool = False, now: Callable[[], datetime] = …) -> SyncReport`. The default `now` is `datetime.now(UTC)`.

- `stale(archive: Archive, kind: Kind, keys: Iterable[str], *, country: str, max_age: timedelta, now: datetime) -> list[str]`: the keys with no answer, or an older one. It's public for part 10's `status`.
