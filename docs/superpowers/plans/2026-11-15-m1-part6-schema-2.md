## Context

Schema part 1 (PR #10) declared 23 Steam tables and the machinery around them:

- the notebook-DDL comparison;
- `ensure_steam_schema`, the fingerprint and the drop-and-recreate.

The spec's milestone 1 still needs the relation, offer, media, store-list, requirement and review tables, plus `wishlist_item` and `followed_app`: 33 tables, all in the notebook's DDL (`tests/fixtures/notebook/steam_database_schema.sql`, lines 209–597). Part 1's final review also left two gaps in the comparison that these tables would hit:

- it can't see generated columns, which `offer_price.discount_pct` is;
- it can't see CHECK constraints, and part 2 has seven.

**Goal:** declare the 33 tables with the notebook's names, every one compared with the notebook's DDL, with the comparison extended to generated columns, defaults, CHECK constraints and partial-index conditions.

**Architecture:**

- **New modules:** one module per section of the notebook's DDL, under `src/steam_manager/db/schema/`:
  - `relations.py`, `offers.py`, `media.py`, `store_lists.py`, `requirements.py`, `reviews.py` and `account.py`;
  - each is imported by `schema/__init__.py`, and each has a mirrored test with a `*_TABLES` constant joined into `STEAM_TABLES` (`tests/steam_manager/db/schema/test_base.py`).
- **Reused from part 1:**
  - `SteamBase`, `STRICT` and `STRICT_WITHOUT_ROWID` (`db/schema/base.py`; `str` → TEXT and `bool` → `Flag` come from its annotation map);
  - `differences()` and `describe()` (`tests/steam_manager/db/schema/_notebook.py`);
  - the `steam_tables` fixture (`tests/steam_manager/db/schema/conftest.py`);
  - `ensure_steam_schema`, which needs no change: the new tables are on `SteamBase.metadata`.

**Tech Stack:** Python 3.15, SQLAlchemy 2.1.8 (`Computed`, `CheckConstraint`, `ForeignKeyConstraint`, `Index(sqlite_where=)`), SQLite STRICT tables, pytest.

**Spec:** `docs/superpowers/specs/2026-11-14-steam-manager-design.md` (*Database*, *Loader*, *Derived figures*, *Reference material*).

## Global Constraints

- **Language and style:** Python `>=3.15`; lines up to 99 characters; complete typing; Sphinx docstrings without `:type:` or `:rtype:`; every column attribute gets its own docstring.
- **Test first:** watch each test fail before writing its code. Tests mirror `src/`: `db/schema/offers.py` → `tests/steam_manager/db/schema/test_offers.py`.
- **Column types:** only `Integer`, `Text`, `Flag` (via annotations) and `Computed`. A notebook INTEGER column is a `bool` (Flag) when its Steam model field is a `bool` (`src/steam_manager/steam/models/*.py`), and an `int` otherwise, as in part 1. Dates are TEXT.
- **Names:** the notebook's table and column names everywhere. Glossary terms: a *rebuild* is replaying the archive; dropping and creating empty tables is *recreating*.
- **Pull request:** one PR, never a draft. Run `uv run prek run --all-files`, `uv run pytest` and the docs build first. Merge by rebase once CI is green. Before 2026-11-18 there is no Sourcery review and no 150,000-character limit.

## Review Focus

1. **A free offer:** `original_price_in_cents` 0 or NULL gives a NULL `discount_pct`, not an error or a division crash. Test in Task 3.
1. **Best offers:** two best offers for one app are refused (`one_best_offer_per_app`), while any number of non-best offers are allowed. Test in Task 3.
1. **Other countries:** a price and an offer's apps in a country outside BR and US (JP) are accepted. Test in Task 3.
1. **CHECK drift:** a CHECK whose text drifts from the notebook's (`'franchize'`) fails the comparison, naming the table and the expression. Test in Task 1.
1. **The `app_asset` rule:** a row that isn't an override but has a `base_filename` is refused, and an override with or without one is accepted. Test in Task 4.

### Task 1: The comparison sees generated columns, defaults, CHECK constraints and index conditions

**Files:** modify `tests/steam_manager/db/schema/_notebook.py`, `test_base.py` and `test_apps.py`.

**Interfaces (produces):**

- `differences(table, *, metadata=None)` keeps its signature. The column line becomes `"{table}.{name} #{cid}: {type} notnull={0|1} pk={n} default={dflt or None} hidden={0|2|3}"`.

- New line kinds:

  - `"{table} check ({expr})"`, once per CHECK in the table's `CREATE TABLE` text;
  - `"{table} generated ({expr})"`, once per `GENERATED ALWAYS AS (…)`;
  - unique indexes become `"{table} unique ({cols})"` or `"{table} unique ({cols}) where {condition}"`, the condition being the text after `WHERE` in the index's `sqlite_schema.sql`.

- **The algorithm the signatures don't fix:** find each `CHECK (` and `GENERATED ALWAYS AS (` in `sqlite_schema.sql` case-insensitively, take the text up to the matching `)` by counting parentheses, then collapse whitespace runs to one space and drop the space after `(` and before `)`.

- [ ] **Step 1: failing tests** in `test_base.py`:

  - `test_a_changed_check_is_caught`: a throwaway `MetaData` whose `app_credit` has `CheckConstraint("role IN ('developer', 'publisher', 'franchize')")`. `differences("app_credit", metadata=…)` contains `"only in the notebook: app_credit check (role IN ('developer', 'publisher', 'franchise'))"` and the `'franchize'` line.
